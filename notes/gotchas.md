# Gotchas

- 2026-04-06: iOS simulator Debug builds can fail with "No script URL provided" when Metro is not running and the app does not have a bundled `main.jsbundle`. The low-risk fix is to force bundling in the "Bundle React Native code and images" build phase for Debug simulator builds and keep a native fallback to `main.jsbundle` in `AppDelegate`.
- 2026-04-06: Embedded iOS targets like Stickers, Widgets, and the Watch app should keep `CURRENT_PROJECT_VERSION` in sync with the container app. If they drift, Xcode validation warns that the extension `CFBundleVersion` must match the parent app.
- 2026-04-15: ATM receive flows must keep a parent route such as `WalletsList` underneath `ReceiveDetails`. Resetting the navigator with only `ReceiveDetails` leaves the close button with nowhere to go, so the QR screen looks stuck even though the UI still renders.
- 2026-05-19: The kiosk scan bay can fail when the receive QR is too large on the phone screen. Keep the ATM receive QR around 220px by default, with the fullscreen ATM QR capped around 260px.
- 2026-06-16: ATM scan-bay readability is about QR *position* as well as size. The scan bay's field of view only covers the upper portion of the presented phone, so the receive QR must sit near the TOP of the screen. In `ReceiveDetails`, the address-tab content uses `qrTopContainer` (`justifyContent: 'flex-start'`) + `qrTopBody` (`flex: 0`), and `centerContent` is enabled only for the BIP47 payment-code tab (`centerContent={currentTab !== segmentControlValues[0]}`). The QR is the first element of the panel (above the badge/instruction). Do not re-center the address tab or move the badge/instruction back above the QR — either pushes the QR down out of the scan bay.
- 2026-06-16: `ReceiveDetails` is now UNIFIED — every entry point (the wallet Receive button, address list, deeplinks, and the ATM onboarding reset) renders the single scan-optimized layout. `isAtmMode` is hard-coded `true` (kept as a named flag so the layout branches stay readable; the old `mode: 'default'` / BIP47-tab / bottom-share branches are now dead code, left in place to avoid an unused-symbol cascade — delete in a dedicated cleanup pass, not piecemeal). The forced seed-backup flow (beforeRemove guard, deposit reminder, backup card) is gated on `isAtmOnboarding = entryPoint === 'atm'`, NOT `isAtmMode`, so only ATM-onboarding wallets get nagged. "Receive with amount" survives as a secondary `AtmActionButton` that opens the existing custom-amount BottomModal; when a custom amount is set, the QR/share/fullscreen use `bip21encoded` (with amount) instead of the raw `address`.
- 2026-08-07: Secondary `AtmActionButton` labels must use `colors.buttonTextColor`, not a fixed `AMERICA_BLUE`; the fixed light-theme color becomes dark-on-dark against `colors.lightButton` in dark mode. Keep the secondary icon blue separately because it sits inside a white icon bubble.
- 2026-08-23: The on-chain Send screen's numeric balance disappeared after choosing full balance because `AmountInput` explicitly returned an empty secondary value for `MAX`, while the selected-wallet footer rendered only the wallet name. Pass `maxAmount` to `AmountInput` and keep `SelectedWalletBalance` visible so dismissing the keyboard never hides the only numeric balance.
- 2026-08-23: Do not assume a brand accent is readable as text just because it is semantically appropriate. American Mint on pale mint was only about 1.4:1 in fee/status badges, and several gray/red combinations also missed WCAG AA. Keep shared foreground/background theme pairs covered by `tests/unit/theme-contrast.test.ts` at 4.5:1 or better; use darker semantic text variants on light surfaces and Mint/white on dark surfaces.
- 2026-08-23: The iOS GitHub Actions workflow uploads `master` pushes to TestFlight but does not submit them to App Review. For production releases, bump every iOS target to a version newer than the public App Store version, let CI produce the signed TestFlight build, then select that processed build in App Store Connect and submit it for review with the intended release behavior.
- 2026-08-23: GitHub-hosted release runners do not have SSH keys for BlueWallet's Git dependencies, and npm can normalize even HTTPS specs back to `ssh://git@github.com/...`. Before `npm ci`, the release workflow must remove `actions/checkout`'s local GitHub `extraheader`, configure the private-repository `GIT_ACCESS_TOKEN`, and install global Git `insteadOf` rules that translate GitHub SSH URLs to HTTPS. Missing the rewrite fails with `Permission denied (publickey)`; authenticating after install fails with `Repository not found`; keeping both auth headers fails with `Duplicate header: Authorization`. A local `npm ci --dry-run` can pass from cache, so the clean hosted runner is authoritative.
- 2026-06-16: To get the ATM QR even higher, the native header is hidden in ATM mode (`setOptions({ headerShown: !isAtmMode })`) since `ReceiveDetails` is a `presentation: 'modal'` with a left close button supplied by `navigationStyle`. Hiding the header removes that close affordance, so a floating close button (absolute, top-left, `testID="NavigationCloseButton"` to keep the Detox `atm-receive.spec.js` tap working, `onPress={goBack}` so the backup-warning `beforeRemove` guard still fires) replaces it. `SafeAreaScrollView` only adds a 5px top pad (not the full inset), so ATM content and the close button are inset-padded via `stylesHook` (`paddingTop: insets.top + 8` / `top: insets.top + 6`) — required so the QR doesn't slide under the status bar on Android full-screen modals (no-op on the iOS sheet where `insets.top` is ~0). Keep these inset styles in `stylesHook`, not inline literals (`react-native/no-inline-styles`).
- 2026-05-21: Xcode 26 simulator builds can fail in the `fmt` pod with `call to consteval function ... is not a constant expression` when `fmt` is compiled as C++20. Keep the `ios/Podfile` post-install override that forces only the `fmt` target to `c++17`, then run `pod install` before rebuilding.
- 2026-05-21: The shared React Native `Button` component can look broken when caller props override its internal style ordering. Keep internal alignment/content styles applied after caller sizing, and for bespoke ATM card actions use a local `Pressable` that owns height, alignment, label sizing, and pressed/disabled states.
- 2026-05-21: The Wallets home screen used an iOS large-title header that pushed the first-run setup content too far down the viewport. Keep the wallet home on a compact header when the branded setup card is the primary onboarding surface.
- 2026-06-16: When validating the iOS app with `xcodebuild`, do NOT pass `-sdk iphonesimulator` for the `BlueWallet` scheme. It forces every embedded target onto the iPhone simulator SDK, and the `BlueWalletWatch` `Interface.storyboard` then fails with `watchOS storyboards do not support target device type "iphone"`, killing the build before the main app compiles. Pass only `-destination 'platform=iOS Simulator,id=<udid>'` and let xcodebuild select the correct SDK per target (watch → watchsimulator). A signing-free compile check: `xcodebuild -workspace ios/BlueWallet.xcworkspace -scheme BlueWallet -configuration Debug -destination 'platform=iOS Simulator,id=<udid>' -derivedDataPath /tmp/bw-sim-build CODE_SIGNING_ALLOWED=NO build`.
